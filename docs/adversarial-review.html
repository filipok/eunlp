1. What changed after re-checking

This report re-verifies the first review. These points were corrected, sharpened or added:

  1. Wrong: -hand anchors. hunalign's -hand=file scores the output against a manual ladder; it is an evaluation flag. Q9 now uses what the hunalign readme documents for this: <p> delimiter lines, or -batch mode.
  2. Inflated: the abbreviation counts. They included the single letters A–Z and entries that also appear in lowercase. F4 now gives the dead multi-letter entries per language: English, Irish and Italian lose most of theirs, Romanian only 1 of 44.
  3. Wrong: the single-letter caveat. Punkt already treats a single capital letter before a capitalised word as an initial and doesn't split there ("Annex A. The Commission…" stays one sentence with or without the list), so lowercasing A–Z changes nothing.
  4. Wrong: the PEP 479 remark. Only generators turn StopIteration into RuntimeError; pairwise() is a plain function, so a Python 3 port would behave the same. Removed from R1.
  5. Wrong: ; as a sentence end. Punkt never splits on ;, so only ? and ! belong in the send-to-hunalign test (Q7).
  6. Wrong: line numbers for down.py and const.py. They came from a listing numbered across two files. All references were re-checked against the source for this report.
  7. Understated: F2. The rewritten text is stored even when the retry also fails, because the fallback Err segment is built from it.
  8. Made precise: F1, F7, F9, Q5. F1's effect depends on which side holds the tab. translate.txt is created by hunalign itself. F9 matters because jsalign exports each cell's innerHTML, so < followed by a letter turns into markup (a bare & is re-serialised correctly). Q5's slack is a few characters per pair, not more.
  9. Made precise: package size. The 25 MB hunalign directory is mostly its 22 MB Hungarian–English sample data; the binary is 820 KB and the object files 1.9 MB (P3).
  10. Withdrawn: drop multi-word idioms from the dictionary. hunalign supports multi-word entries; the real problems are diacritics and tokenisation (Q6).
  11. Added. R8 (editor scripts without integrity hashes), the over=False half of R3, and R6's check that no EU-language abbreviation can crash the regex.
  12. Not verifiable here. Live Eur-Lex and MaxCDN were blocked by this environment's network policy, so R4 and R5 come from code reading. The jsalign files on S3 answered HTTP 200.

2. Findings

Silent output corruption

F1 · HighTabs inside a paragraph shift the pair columns

align/convert.py:313 · align/align.py:200, 267, 288 · align/l2t_new.py:69-74 · align/convert.py:64-66, 124-125

Aligned pairs travel between functions as tab-separated strings (tag\ttarget\tsource). file_to_list collapses runs of spaces (' +') but leaves tabs alone, so a tab inside a paragraph adds a column. A tab in the target puts the rest of the target into the source field and drops the real source; a tab in the source drops everything after it. The TMX re-aligner doesn't clean its input at all.

Evidence: The real file_to_list returns 'Table 1\tAmount in EUR\tYear' unchanged, and the pair Nai\tTextul\tţintă\tSource text parses as source ţintă, target Textul. A tab right after list numbering is removed by numbering_separator, except on the first line of a document.

Fix: Collapse [ \t]+ (and stray \r) in file_to_list. Better: pass (tag, target, source) tuples instead of tab-separated strings.

F2 · HighThe retry rewrites the text it stores

align/align.py:247-248, 262-267

When check_hunalign rejects the first result, tmp_aligner rewrites both texts with (\D{3,20})\.(\D{3,20}) → \1. \2, which adds a space after a dot between non-digit characters, and aligns again. The rewritten source and target are what get stored, whether the retry passes (Hun) or fails (Err), so every paragraph whose first attempt was rejected comes out altered in both the TMX and the editor.

Evidence: eur-lex.europa.eu → eur-lex. europa.eu; info@ec.europa.eu → info@ec. europa.eu; www.consilium.europa.eu. → www.consilium.europa. eu.

Fix: Use the rewrite only to decide where to split, store the original text, and leave URLs and e-mail addresses alone.

F3 · MediumThe footnote-spacing fix stops after 32 matches

align/convert.py:319

re.sub(pattern, repl, text, re.UNICODE) passes the flag as the fourth positional argument, which is count. re.UNICODE is 32 in both Python 2 and 3.

Evidence: With 40 footnote references in the text, 32 were fixed.

Fix: flags=re.UNICODE.

F4 · HighCapitalised abbreviations never stop a sentence split

align/util.py:27

Punkt lowercases a token before looking it up in abbrev_types, but the lists are loaded with their original case, so entries such as Mr, Dr, Art and No have no effect.

Evidence: As shipped: ['See Art.', '5 and No.', '12 of the annex.', 'It applies.']. Lowercased: ['See Art. 5 and No. 12 of the annex.', 'It applies.']. Dead multi-letter entries (capitalised, with no lowercase twin): en 60/74, it 62/70, ga 60/74, es 163/300, cs 212/413, hu 227/1414, de 85/241, fr 43/99, pt 33/135; ro only 1/44.

Fix: set(a.lower() for a in abbreviation_loader(ab_file)).

F5 · LowThe French closing-quote merge never runs on the target side

align/align.py:130

note[0] == 6 compares a string with an integer, so it is always false. The source side (line 125) correctly uses '6'.

Fix: note[0] == '6', ideally through one helper used for both sides.

F6 · Mediumdiacritice.py turns Ş into a control character

diacritice.py:23

u'\0218' is an octal escape: the two characters '\x11' and '8', not U+0218 (Ș). Every capital Ş (U+015E) in the file is replaced by a control character followed by 8.

Evidence: repr('\0218') is '\x118', length 2.

Fix: u'\u0218'.

Data loss and security

F7 · HighFiles in the working directory are emptied or deleted

align/util.py:98-99 · align/align.py:175, 419-422

The dictionary path is <cwd>/<src><tgt>.dic. With make_dic=False, which both working CLIs pass, parallel_aligner truncates that file. celex_aligner then deletes it, and also deletes translate.txt, which hunalign itself creates or truncates in the working directory. A user's own enro.dic or translate.txt there is lost.

Fix: Keep the dictionary and hunalign's working files in a private temporary directory, run hunalign with cwd set to it, and never delete files the run didn't create.

F8 · MediumTemporary files are predictable and shared

align/align.py:161-162, 225-228, 340, 352

Every run uses /tmp/eunlp, with names from randint(0, 100000). Parallel jobs (for example under Wooey) can draw the same number and overwrite each other's files. A second local user can't write into the directory the first one created, and whoever creates the directory, or symlinks inside it, first can redirect the writes. Two processes starting together can both call makedirs, and one crashes.

Fix: tempfile.mkdtemp() per run with try/finally cleanup. This also fixes the leaks in R1.

F9 · MediumThe HTML editor output isn't escaped

align/const.py:39-40, 44-49, 55-57, 86 · align/convert.py:45, 79-80, 225-231

CELL.format inserts segment text raw, and Jinja's Template doesn't autoescape by default. BeautifulSoup's get_text() has already turned &lt; back into <. jsalign 0.8 builds the exported TMX from each cell's innerHTML, so a literal < followed by a letter becomes a real element in the editor and is exported as markup. The CELEX number also reaches <title>, a <meta> attribute and the TMX note unescaped, and characters that are invalid in XML (form feed and the like) aren't removed.

Evidence: Template('{{x}}').render(x='<b>&') returns <b>&.

Fix: HTML-escape cell text and render with autoescape=True, escape the note, and strip XML-invalid characters before writing the TMX.

F10 · Mediumcelex_list.py fetches any URL, and no request has a timeout

celex_list.py:61-68 · align/down.py:30

The XML-list argument goes straight to urlopen, which accepts file:// URLs and internal hosts, and the response is saved as file_list.xml in the working directory. If a web front end such as Wooey offers job files for download, that exposes local files. No urlopen call sets a timeout, so one stalled connection hangs the job.

Fix: Accept only https:// (or only Eur-Lex hosts) and pass timeout= on every request.

Robustness

R1 · MediumHunalign failures are hidden

align/align.py:45-49, 268-271, 383-386 · align/l2t_new.py:27-31

The exit code and stderr are thrown away. A crash leaves an empty ladder file, which surfaces as a StopIteration from pairwise() and sends the whole document to manual alignment with no reason logged. Temporary files are removed only on success.

Fix: Check returncode, log stderr, raise a specific exception, and clean up in finally.

R2 · LowA fresh download and a cached re-run are processed differently

align/down.py:29-43

A fresh download is a byte string, but a cached file is read back as decoded text. The \xa0 in the word-spacing pattern can only match decoded text, so if the page has a literal no-break space there, a re-run splits paragraphs differently from the first run.

Fix: Decode the response (charset from the headers or <meta>) before any substitution.

R3 · LowStale caches and outputs are reused without checks

align/down.py:29, 100 · align/align.py:72-77, 416

Cached .html and .txt files are used whenever they exist, so a saved error page is reused forever. celex_aligner hard-codes over=False, so a document that once fell back to manual alignment is skipped on every later run, even after the aligner improves.

Fix: Add an overwrite option to the CLIs and validate cached pages.

R4 · LowThe big-file link may be relative (not verified)

align/down.py:116-122

The href from the alert-warning box goes to urlopen as is. If Eur-Lex serves it as a relative URL, urlopen raises ValueError, which celex_aligner doesn't catch.

Fix: urljoin() it with the page URL, and catch ValueError and URLError.

R5 · MediumHTML extraction depends on fixed child positions

align/down.py:115, 127-129

find_div.contents[1].contents[1] and contents[8].contents[5]… break on any whitespace or layout change; the history already has two Eur-Lex layout fixes. Current Eur-Lex couldn't be checked from here.

Fix: Select elements by id or class, or fetch the document-only rendition (/legal-content/<LANG>/TXT/HTML/?uri=CELEX:…).

R6 · LowAbbreviation handling is inconsistent

align/convert.py:284-294 · align/util.py:24-29

numbering_separator loads the list without checking that it exists (an IOError for a language without one), while sentence_splitter tolerates a missing list. Each abbreviation is pasted into a regex unescaped, so the dot in entries like i.e or z.B matches any character. No entry in the EU-language lists can crash the regex.

Fix: One loader with a missing-file fallback, and re.escape(abb).

R7 · LowThe TMX re-aligner assumes one exact structure

align/align.py:431-442

It indexes tu children by position (element[2][0]), fails on an empty segment (.text is None), and creates <src><tgt>.dic in the working directory without removing it.

Fix: Find each tuv by xml:lang, treat None as an empty string, and use a temporary dictionary.

R8 · LowThe editor loads third-party scripts without integrity checks

align/const.py:73-85

Every generated HTML file loads jsalign and rangy from S3 buckets and Bootstrap from MaxCDN, with no Subresource Integrity hashes. The jsalign files still answer (HTTP 200), but if a bucket is ever deleted its name can be registered by someone else, and every file generated so far would run their script. The editor also needs network access to work at all.

Fix: Add integrity= hashes, or ship the scripts alongside the output.

Code health, packaging and tests

celex_multi.py:21 · get_EP_text.py:29-37 · get_PV_CRE.py:40 · align/util.py:34, 45, 103 · align/down.py:204 · align/convert.py:164

celex_multi.py imports align.multi, which doesn't exist. get_EP_text.py and get_PV_CRE.py call functions on align.align that live in util or down (both scripts are marked TODO broken). make_ep_link, make_ep_sub_link, make_paths_multi, remove_newlines and dirty_ttx_to_tmx have no working caller in the repository.

It says the aligner retries after removing very short lines when the counts differ. smart_aligner never passes tries>0; the changelog records the removal in 0.8.2.

MANIFEST.in includes README.rst, which doesn't exist. recursive-include align/hunalign-1.1 * ships 22 MB of hunalign's Hungarian–English sample data that eunlp never uses, a prebuilt 820 KB x86-64 binary with no build step or provenance, and 1.9 MB of object files.

urllib2, unicode() and print statements throughout; current nltk and beautifulsoup4 no longer support Python 2. The nltk tokenizer data the code needs isn't mentioned in the README, and word_tokenize always uses the English model.

3. Alignment quality improvements

Ordered by expected impact.

Q1Align paragraphs around anchors instead of all-or-nothing

align/align.py:86-90

When the paragraph counts differ, the whole document goes to manual alignment. When two errors cancel out, the counts match and everything between them is silently shifted (the notes file records a "SILENT FAIL"). Match anchors first (numbers and references such as 1024/2013, (12), Article 5, dates), align the stretches between anchors with Gale–Church or hunalign over paragraphs, and send only uncertain stretches to manual review.

Q2Check the numbers in every pair

align/align.py:193-211

EU texts keep digits identical across languages. Comparing the digit sequences of each source/target pair is a cheap, strong drift detector, and it also covers the short pairs that never reach hunalign.

Q3Use hunalign's confidence score

align/align.py:288-289

check_hunalign throws away the ladder score (split_line[0]). Reject low-scoring beads and tag borderline ones for review.

Q4Calibrate the length ratio per language pair

align/align.py:299

The 0.5–2.0 character ratio is the same for every language pair. Estimate the typical ratio from the document's own paragraph pairs and flag pairs far from it; the same test catches drift in pairs hunalign never sees.

Q5Compare text, not character counts, for dropped text

align/align.py:291-292, 305

The count-based check has a few characters of slack per pair, plus four per sentence merged with ~~~ . Compare the joined output with the input after removing whitespace and separators.

Q6Turn the dictionaries on, after fixing them

celex.py:51 · celex_list.py:84, 103, 120 · align/util.py:131-156

Both working CLIs pass make_dic=False, so hunalign aligns on sentence length alone and the 5.5 MB in data_raw is unused. Before enabling them: the Romanian list has 12,632 empty entries out of 19,277 and only cedilla letters (4,712 ş/ţ, no ș/ț), so it can't match text written with comma-below letters. Normalise diacritics and tokenise entries the way the .tok input is tokenised.

Q7Improve sentence splitting

align/util.py:17-31 · align/align.py:179, 195-198 · align/nonbreaking_prefixes/

Fix F4 first. Fill the thin lists: el has 3 entries; hr, lt, lv, mt and fi are almost only single letters; ga is a copy of en. Count ? and ! as sentence ends in the send-to-hunalign test (Punkt never splits on ;), and base the short-paragraph decision on both sides, not only the source.

Q8Use one segmentation for both paths

align/align.py:121-136 vs 146-190

french_quotes and full sentence splitting only run in the manual fallback, so the same document is segmented differently depending on which path it took.

Q9Run hunalign once per document

align/align.py:26-49, 214-272

Write all long paragraphs to one file pair with a line containing only <p> between paragraphs (hunalign aligns these only with each other), or use -batch. That removes one subprocess per paragraph and gives -realign and the dictionary enough text to help.
